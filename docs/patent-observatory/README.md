# ISTAT–CNR Patent Semantic Observatory

**Static, GitHub Pages–ready research website** for exploring semantic heterogeneity in a WIPO-stratified sample of 63,968 patent publications. The site was built using the user's completed analyses from Notebooks 03–05, 09–14 and the user-provided exports. It does not retrain models or compute new experimental results.

## What is inside

| Page | Evidence | Cohort |
|---|---|---|
| Research answer | Summary of supported findings and limitations; nine-model WIPO AMI and within-office similarity | Full and pilot, separately labeled |
| The sample | WIPO sectors, office counts, 37 offices, 625 IPC subclasses, deduplication, MiniLM reference heatmap | Structural EDA and full-corpus reference |
| Embedding comparison | WIPO AMI, cosine silhouette, stability ARI, office AMI, cross-model ARI; pilot vs full | 6,400 and 63,968 |
| Clustering robustness | K grid, spherical K-Means, HDBSCAN coverage, within-office similarity | Pilot 6,400 |
| Cluster composition | CN shares, effective WIPO fields and leading WIPO fields by cluster | Pilot 6,400 |
| Explore patents | Interactive UMAP HTML maps, centroid-distance plots, full patent abstracts, peripheral/boundary examples | UMAP 2,400; examples pilot/full as labeled |
| Meeting briefing | Suggested 5-step research narrative and 27 illustrative patents | Cross-analysis |
| Methods & sources | Caveats, references, CSV exports, provenance | — |

**Scientific framing:** The sample exhibits measured technological differentiation across embeddings; this is not equivalent to a unique 'true' technology partition. The comparative proposition *more heterogeneous than the old sample* is **not tested** by these analyses alone.

## Compare three embedding models

Open [`model-comparison.html`](model-comparison.html) in a browser to explore the K=8 cluster cards for Qwen 4B, Patent SBERT-adapt-ub, and Pat-SPECTER, on the full corpus and with CN excluded. Keep `model-comparison-data.js` beside the HTML file; it contains the comparison data used by the page. Both files work directly from a local clone and do not require a server or a deployment.

## Open locally

**Simplest:** unzip the package, then double-click `index.html` in Chrome, Firefox or Safari. Plotly JavaScript is bundled locally in `assets/plotly.min.js` so the charts do not require an internet connection. Google Patents links require internet when clicked.

**Optional local server:** from this directory run:

```bash
python3 -m http.server 8000
```

and open `http://localhost:8000/`.

## Maps: two uploaded, seven already generated on Drive

The initial starter ZIP contains the two real UMAP maps uploaded by the researcher: **BGE-M3** and **Patent SBERT**. These both represent 2,400 pilot patents, with their own coordinates and click-to-read full abstracts. For **all nine models**, the dashboard provides an interactive centroid-distance diagnostic and patent cards even before the remaining maps are imported.

All nine UMAPs were generated by Notebook 14 and were saved in Google Drive at:

```
MyDrive/istat_patents/semantic_results_v11_clustering_robustness/
  pilot_200_per_field/all_texts/interactive/
     14_patent_map_<model>.html
```

The companion **`15_complete_dashboard_maps_colab.ipynb`** copies them into the site and produces a finished ZIP. It does **not** rerun UMAP or any other computation. You can also copy the missing HTML files manually into `maps/` and update `data/map_manifest.js` to list the available model folder names.

**Do not say the UMAP maps contain 63,968 points.** They show 2,400 selected pilot publications, independently projected for each model. The dashboard's model-comparison tables separately use the full 63,968-publication sample.

## Data provenance and scientific qualifications

- Hugging Face repository: https://huggingface.co/datasets/istat-ai/wipo32-patent-embeddings
- Dataset commit: `e570ab0121c6dff0e61b05b64dd7ee21b98b78b7`
- One WIPO selection field per patent is used for AMI, even though patents may match more than one technology concordance field.
- Data were designed to be evenly sampled by 32 technology fields, not by country, office, year or global frequency.
- All nine embedding representations were L2 normalized for clustering; original MiniLM used overlapping chunks, new models had model-specific token limits and no chunking.
- Model-specific silhouette metrics use different geometries; comparison is descriptive.
- HDBSCAN noise was high at the tested parameters, and assigned-only metrics cannot be directly compared against full-coverage K-Means.
- Review examples are illustrations rather than a representative scored human-validation study.
- Full scientific reproducibility requires access to the source embeddings and executed notebooks; all provided source summary tables used by this website are included in `downloads/`.

## Update results

The file `data/results.js` is prebuilt from the supplied CSVs and contains the data used by charts and the patent inspector. A researcher can regenerate it from new exports or update the sources and rebuild the static site. The site itself makes no hidden calls to third-party ML systems.
